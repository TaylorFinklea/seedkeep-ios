# N2 — On-device replacements (contract)

Plan: umbrella `.docs/ai/phases/2026-10-20-apple-only-plan.md` (approved
2026-10-20, N1 + N2). N1 contract: `2026-10-20-n1-apple-only-entry.md`.
Branch: `redesign/n1-apple-only`, continuing after the N1 commit.

Revised after GPT-6.1 Sol's critique (verdict on the first draft: revise
before implementation). "Delete Seedkeep data" moves to its own contract,
N2-E. It needs CloudKit zone-deletion handling across devices; today the
engine recreates a deleted zone (`HouseholdSyncEngine.swift:544`) and
ignores fetched zone deletions (`:399`). The regional extension planting
calendars are left out. The server plan says they were unreviewed starter
dates (`seedkeep-server/.docs/ai/plans/2026-05-21-extension-calendars-server.md`,
around line 490), so N2 uses the rule engine only.

N1 hid every server-backed feature behind `ServerRetirement.isRetired`. N2
brings back on the device:
- home location
- planting recommendations
- packet scanning
- random pick

The catalog (barcode lookup, catalog detail, corrections, contributions)
stays hidden.

## Invariants (all slices)

1. **No server request.** Nothing in N2 calls `SeedkeepClient`. Paths N2
   touches that still have a legacy server fallback are gated at the call
   site: `AddSeedView`'s `flushPending()` and the seed-photo upload's server
   branch. `ServerRetirement.refusals` stays 0.
2. **No schema change.** No new CloudKit record types or fields.
   Device-local state lives in UserDefaults or the app container.
3. **Offline.** Location lookup and recommendations need no network.
   WeatherKit refinement stays best-effort.
4. BYOK scanning stays (owner, 2026-10-20).
5. Workbench screens use Workbench tokens; older screens keep their style.
   Match the surrounding code's style and comment density.
6. **Dates.** "Today" is the user's local date in
   `Calendar(identifier: .gregorian)` with `TimeZone.current`. Day
   arithmetic runs on those year-month-day components in a UTC Gregorian
   calendar, matching the server's UTC-midnight math. **Intentional
   differences from the server:** a local date rather than UTC, no AI
   fallback (a low-confidence rule window is shown with its confidence), and
   no extension calendars.

## Slice C — climate data, home location, on-device recommendations

### C1. Bundled climate data

`scripts/build-climate-resources.py` (`python3 -I`, standard library,
idempotent) generates `Seedkeep/Resources/Climate/zip_climate.csv` from
`~/git/seedkeep-server/data/zip_locations.csv` (read-only). Columns are
`zip,lat,lon,zone`, covering all 33,751 rows, about 0.9 MB.

Swift tables:
- **Zone to frost dates:** `(avgLastFrost, avgFirstFrost)` as `MM-DD`,
  ported exactly from `seedkeep-server/scripts/build-zip-dataset.ts` (the
  26-entry `ZONE_FROST_FALLBACK`).
- **ZIP3 to state:** not needed (extension calendars are out).

`Seedkeep/Resources/Climate/SOURCES.md` (a repo doc; it may be bundled)
records:
- USDA Plant Hardiness Zone Map 2023, through the phzmapi.org mirror, with
  the official source `https://planthardiness.ars.usda.gov/`
- the U.S. Census 2024 ZCTA Gazetteer (public domain)
- frost dates: a zone-level estimate from NOAA 1991–2020 normals and
  horticultural references, with no accuracy claim
- the build date and the script

Release checklist item (N3, owner): verify the redistribution and
attribution terms for the zone data.

**Settings ▸ About ▸ Data sources** shows short attributions: USDA ARS
Plant Hardiness Zone Map (2023); U.S. Census Bureau; frost dates estimated
from the hardiness zone.

```swift
struct HomeClimate: Codable, Equatable, Sendable {
    let zip: String; let latitude: Double; let longitude: Double
    let usdaZone: String; let avgLastFrost: String; let avgFirstFrost: String   // "MM-DD"
}
enum ClimateLookup {
    static func climate(forZip zip: String) -> HomeClimate?   // nil: unknown or malformed (not exactly 5 digits)
}
```

The table loads lazily, once, thread-safely (actor or lock), off the main
thread on first use. A test confirms a known ZIP and an unknown one.

### C3. `PlantingEngine` (pure, no I/O): `Seedkeep/Core/Recommendation/PlantingEngine.swift`

Port exactly `seedkeep-server/src/lib/recommendation/engine.ts`
(`computeRuleBaseline`) and `projection.ts` (`projectWindow`).

```swift
struct PlantingRecommendation: Equatable, Sendable {
    let source: String                    // "rule"
    let confidence: Double                // rounded to 2 dp, as the server
    let verdict: String                   // too_early | plant_soon | plant_now | late | too_late | unknown
    let rangeStart: String?, rangeEnd: String?      // "YYYY-MM-DD"
    let indoorStart: String?, indoorEnd: String?
    let scoresAnchorDate: String
    let dailyScores: [Double]             // always 60
    let reasoning: String?                // nil (rule source)
}
enum PlantingEngine {
    static func recommend(growingInfo: GrowingInfoSnapshot, climate: HomeClimate,
                          today: (year: Int, month: Int, day: Int)) -> PlantingRecommendation
}
```

Constants as in the TypeScript:
- maturity buffer 14 days
- indoor start 56 to 42 days before
- frost offsets: tender or nil 0, half_hardy −7, hardy −28
- confidence penalties: frost −0.25, soil −0.20, sow −0.15, maturity −0.10,
  zone −0.10 (only outside zones 3–10)
- an inverted window caps confidence at 0.59
- projection: 60 days, ramp `min(7, len/2)`, plant-now fraction 0.4,
  `days()` rounded

No window → `unknown` with 60 zeros.

**Tests:**
- golden cases ported from `seedkeep-server/src/lib/recommendation/__tests__/engine.test.ts`
  and the projection tests (read them)
- each verdict boundary
- an inverted window
- missing maturity
- a short window (`len < 14`, ramp under 7)
- confidence rounding
- year rollover
- a local date east and west of UTC
- a non-Gregorian `Calendar.current` (the engine must not use it)

## Slice D — scanning saves locally

1. **Flow.** No barcode step: the scanner starts at the front and back
   photos; remove the catalog lookup call. The camera stays iOS-only;
   shared prefill types compile on macOS.
2. **Result.** Free (on-device) and BYOK results do not call
   `submitPreExtracted`. The flow returns `.localExtraction(scanID: UUID,
   fields: WireResponses.ExtractionFields)`. The two photos are already
   staged (step 3).
3. **Staging** (`ScanPhotoStaging`):
   - when the photos are captured, write both through the saved-photo
     pipeline (`PhotoResizer`'s saved-photo budget, not the 4 MB extraction
     budget) to `Application Support/ScanStaging/<scanID>/front.jpg` and
     `back.jpg`
   - Cancel cancels the extraction task (structured `Task`, generation
     check before completion) and deletes the staging directory
   - at launch, delete staging directories older than 24 hours whose scan
     never reached save
4. **`AddSeedView`:**
   - **Prefill.** `.localExtraction` maps the fields like `.preExtraction`;
     the snapshot uses `snapshot(from:)`; no `catalogID`.
   - **Seed and metadata.** `enqueueCreateSeed`, then `setLocalGrowingInfo`
     and `setLocalCustomType`. Failures must surface; no `try?` swallowing
     in the new path. Gate `flushPending()` on
     `!ServerRetirement.isRetired`.
   - **Photos.** Attach the staged front and back as seed photos, with
     **stable photo IDs** derived from `scanID` (for example
     `scan-<scanID>-front`). A retry or relaunch never duplicates them; add
     an ID parameter to the `SyncEngine` seed-photo creation if needed. The
     front's `capturedAt` is earlier than the back's, so the front is the
     cover under the existing ordering. Add an `id` tie-breaker to that sort.
   - **Resume.** As implemented after review: the seed ID is chosen up
     front, and `manifest.json` records `{seedID, iCloud user, household,
     pending growing info and custom type}` BEFORE the seed is created. Each
     detail and each attached side gets an applied flag. Launch resume runs
     only after a verified identity, for manifests in the current scope; it
     replays unapplied details, then attaches unattached sides (stable IDs
     make this idempotent). A seed that isn't found keeps its staging; a
     tombstoned seed, or a manifest older than 7 days, discards it. Both N1
     erasers and the coordinator's account wipe purge all staging.
   - **Failure.** If a photo attach fails, the seed stays saved, the banner
     says so, and the launch resume retries.
5. Restore the scan entry points N1 hid: Library, and the Workbench toolbar
   on iOS and iPad. Hosted stays hidden.
6. **Tests:**
   - stable IDs: no duplicates on retry
   - the cover is the front
   - Cancel deletes the staging and drops a late extraction result
   - launch resume attaches the missing back photo
   - stale staging cleanup
   - a metadata-save failure surfaces
   - the refusal count stays 0 through save

## Slice R — random pick

`RandomPickView` picks locally:
- **Candidates:** non-deleted seeds with `stateRaw == "active"` in the
  active garden (`appEnv.activeGardenHouseholdID`).
- **Weight:** `yearPacked == nil ? 2 : max(1, currentYear − yearPacked)`,
  where `currentYear` is the local Gregorian year.
- **Picking:** the cumulative-weight walk from
  `seedkeep-server/src/lib/randomPick.ts` (target = rng × total; subtract
  until ≤ 0; fall back to the last seed). The RNG is injectable.
- **Card:** shows `displayName`, company, packets, year and notes; tapping
  opens the seed's detail where navigation allows.
- **Empty:** "No active seeds to pick from."
- Restore the Library entry point.
- **Tests:** the weights, an empty garden, the active-garden scope, the
  walk's boundaries, and the floating-point fallback.
